# Desktop UI audit — October 18, 2026

Reviewed revision: `1c7dab2`. Scope: the current Qt desktop interface, embedded graph controls,
dependency table, source navigation, asynchronous work and analysis controls. This is an audit,
not an implementation of another requirements-plan phase. Production code was not changed.

## Assessment

The interface has useful foundations: consistent visual styling, entity/file/directory views,
a dependency table with pagination and export, source evidence, offline graph rendering and
background query infrastructure. However, its integration has significant defects in window
layout, project context, cancellation and presentation of evidence. It needs corrective work
before its displayed state can be treated as consistently reliable.

The existing UI tests pass, but do not cover these failure modes. In particular, exercising
internal JavaScript methods and checking loaded data does not establish that controls are
visible, keyboard accessible, or that a user is taken to the newly loaded evidence.

## Evidence and limits

- All **20 existing UI tests passed**, in 24.59 s.
- **11 audit probes reproduced the defects described below**: ten probes in 10.45 s and the
  cancellation probe in 2.43 s. These probes assert the observed defective behavior; their
  passing result is evidence of reproduction, not a quality gate for the desired behavior.
- One live Windows interface capture and its accessibility tree were inspected. The app
  restored an existing project. The window later became unavailable to the automation tool;
  remaining checks used isolated Qt test windows and synthetic fixtures.
- The Qt probes ran outside the tool sandbox, with `QTWEBENGINE_DISABLE_SANDBOX=1` and
  `QTWEBENGINE_CHROMIUM_FLAGS=--disable-gpu` for those test processes. These settings were not

- No full screen-reader session, multi-monitor matrix, high-DPI matrix, hardware-rendering
  performance benchmark, packaged-build audit or real-model workflow was performed.
- The previous Phase 1 validation is already recorded in `phase1_engine_reliability.md`.

## Findings, ordered by priority

P1 denotes a high-impact defect to address first. P2 denotes a concrete functional or
accessibility defect to address in the following correction work.

### UI-01 — P1: layout requires more width than ordinary desktop screens provide

**Observed:** after opening the small mixed-language fixture and requesting a 1280 × 800
window, both the actual width and `minimumSizeHint().width()` were **2370 px**. The live
1536 px-wide desktop capture also showed the right side extending beyond the visible area.
At an 800 px graph viewport, the web toolbar ended at y=84 while the filters began at y=64:
the two panels overlap by **20 px**.

**Cause:** graph buttons and the entire long status message share one non-wrapping horizontal
layout. The navigation column has a fixed width, and other labels add substantial minimum
width. Inside the graph, the toolbar can wrap but the filter panel has a fixed top position.

**Locations:** `ui/graph3d_view.py:163–170`, `ui/main_window.py:316`,
`ui/web/view3d.html:16–28` (all paths below `src/codegraph_sci/`).

**Correction:** put graph status on its own wrapping/elided row; use collapsible or responsive
control groups; allow the source panel and navigation to collapse; lay out web controls in
normal flow or calculate their placement from actual dimensions.

**Acceptance:** at 1280 × 800 and 1366 × 768, all primary actions remain reachable without
moving the window off-screen. At 800 px graph width, toolbar and filters have no overlapping
rectangles. Repeat at 100%, 125% and 150% scaling.

### UI-02 — P1: project changes can display the previous project's selection and source

**Observed:** select `f:kernel` in the mixed-language fixture, then open the independent
Fortran fixture. `current.uid` remains `f:kernel` and the inspector still displays
`fsrc/kernel.f90` under the new project's heading.

Project switching does not clear the current selection, source, search results, call lists
or old query callbacks. There is a related invalidation defect: `QueryRunner.cancel_all()`
clears generation counters. Submit generation 1, cancel, then submit the same key again:
the old generation 1 result is accepted. This was independently reproduced with controlled
signal delivery.

**Locations:** `ui/main_window.py:510–548`, `ui/workers.py:54–80`.

**Correction:** reset all project-scoped UI state and invalidate old work on project change.
Use a monotonically increasing project/request epoch that cannot collide after cancellation;
callbacks must carry the database/project identity they belong to.

**Acceptance:** delay source and symbol requests for project A, switch to B, then release
those requests. No A data may appear in B. With identical symbol names in both projects,
selection and source still refer only to B.

### UI-03 — P1: Cancel does not stop descendant extraction work

**Observed:** a harmless parent command started through `CgsProcess` spawned a child writing
a heartbeat. After `cancel(wait=True)` killed the parent, the child continued writing. The
child exited automatically after two seconds; no persistent test process was left behind.

`CgsProcess.cancel()` calls `QProcess.kill()`, which bypasses the engine's cooperative
cancellation and cleanup path. The test confirms the process-management mechanism; it did
not intentionally strand a real parser. Continuing extraction workers are the corresponding
risk when this mechanism is used for a scan.

**Location:** `ui/workers.py:116–122`; callers at `ui/main_window.py:554–560` and `510–514`.

**Correction:** request cooperative scan cancellation over an explicit local control channel,
wait for worker cleanup, then use bounded process-tree termination if necessary. Apply the
same policy when switching projects or closing the window. Report cancellation as complete
only after cleanup.

**Acceptance:** cancel a scan with one blocked and one healthy worker, including from the
window-close path. No descendants remain, and the previous committed database is preserved.

### UI-04 — P2: the call tree performs database queries on the GUI thread

**Observed:** intercepting `GraphQuery.children` during `CallTreeModel.fetchMore()` shows it
running on `QApplication.thread()`. The model constructor also opens its connection and
loads the root node synchronously. The tree is built when a symbol is selected, even if the
tree page is not the current view.

**Locations:** `ui/models.py:40–52,106–109`; `ui/main_window.py:822–832`.

**Impact:** a slow disk, database contention or expensive query can block painting and input.
This violates the project's background-query requirement. The audit verified thread affinity;
it did not claim a measured long freeze on a large corpus.

**Correction:** fetch tree pages in the query runner, with per-model generations and loading
rows; update the Qt model on the GUI thread after completion. Do not share a SQLite connection
between threads.

**Acceptance:** inject a delayed child query. The window keeps repainting, responds to input,
and discards results after the root or project changes.

### UI-05 — P2: graph evidence loads invisibly and its filter controls can be misleading

**Observed:** click a graph edge. The dependency table receives the relevant rows, but the
active view remains the graph. For file and folder edges there is no equivalent visible
source-list fallback. Set the table's status to `external`, then request graph evidence:
the control still reads `external` while the effective filter has no status restriction.

The edge event includes its relationship kind, but `link_evidence(source, target)` does not
use it. Consequently a drill-down can include other relationship kinds between the same pair.

**Locations:** `ui/main_window.py:261–262`, `ui/graph3d_view.py:handle_event`,
`ui/deps_view.py:206–224`, `query/api.py:1389–1395`.

**Correction:** open a visible evidence drawer or activate Dependencies on edge selection;
show an explicit caller/target/relationship breadcrumb and clear/reset action. Keep the
displayed filter controls synchronized with the effective query, including group drill-down.

**Acceptance:** a file/folder/entity edge click visibly opens its matching occurrences without
another navigation action. Existing filters cannot silently contradict the rows. Where two
relationship types connect the same pair, the selected type is respected.

### UI-06 — P2: grouped call confidence is overstated

**Observed:** a group containing one `heuristic` site and one `exact` site is labelled `exact`.
The selection expression takes a minimum over a *negative* rank, selecting the strongest
confidence rather than the weakest.

**Location:** `ui/main_window.py:765–766`.

**Correction:** display the weakest confidence or an explicit mixed-confidence summary;
retain each occurrence's confidence in the expanded rows.

**Acceptance:** a mixed heuristic/exact group is never presented simply as exact.

### UI-07 — P2: process failures can leave a permanently busy or misleading interface

**Observed:** start a nonexistent executable: `FailedToStart` occurs, but Analyze stays
disabled and Cancel enabled. `CgsProcess` listens to `finished`, not `errorOccurred`.
Separately, a scan ending with exit code 2 and a normal error message, without a Python
traceback, can leave the status reading `Analysis in progress…` and show no failure notice.

**Locations:** `ui/workers.py:99–113`, `ui/main_window.py:579–590`.

**Correction:** handle failed start, crash, cancellation and nonzero completion explicitly.
Always restore controls; display a concise error with optional diagnostic details and a
retry action. Treat expected cancellation separately from failure.

**Acceptance:** missing executable, invalid profile and parser-process crash each terminate
the busy state and show an actionable error; cancelling does not show a spurious crash.

### UI-08 — P2: filters disagree with badges and are not consistently applied across views

**Observed:** with an exact-only confidence filter, a report containing one heuristic caller
produces the tab `Callers (0)` while the prominent badge still says `1 callers`. The summary
also uses the unfiltered count. Confidence/AI/ambiguity filters are applied in `_fill_links`,
while graph and tree reloads do not receive the same complete filter state.

**Locations:** `ui/main_window.py:744–800,822–832`.

**Correction:** define whether each filter is global or view-local. Show filtered/total counts
explicitly, and derive all affected views from the same filter state. A global-looking Filters
popover should not silently change only one panel.

**Acceptance:** apply every filter independently and in combination; badges, lists, summaries
and graph counts either agree or clearly label their different scopes.

### UI-09 — P2: primary icon actions are unavailable to normal keyboard focus

**Observed:** Analysis, Filters and Show in use `Qt.NoFocus`, have no explicit accessible
name, and appear as unnamed buttons in the live accessibility tree. The icon rail also uses
`NoFocus`. Tooltips help mouse users but do not provide a reliable keyboard navigation path.

**Locations:** `ui/shell.py:181–191`, `ui/main_window.py:414–421`.

**Correction:** use normal keyboard focus, meaningful accessible names/descriptions and
visible focus indicators. Provide shortcuts or menu actions for Analyze, Cancel, Filters,
Search and source navigation; make popovers usable with Tab, Enter and Escape.

**Acceptance:** complete open → analyze → search → inspect → filter → cancel without a mouse.
Inspect accessible names and verify behavior with a real screen reader.

## Additional UX improvements

These are design recommendations, separate from the reproduced defects:

- Use one clear primary project action and reduce competition between the large orange
  selection banner, icon-only actions and two graph toolbars.
- Explain the scopes of the sidebar search and graph-local search. The latter currently
  focuses a node inside the canvas without notifying the host selection handler
  (`ui/web/view3d.js:399–405`), so the inspector can still describe another entity.
- Add explicit empty, loading, no-match and unavailable-data states. A blank table or graph
  should distinguish these situations.
- Add source line numbers and a visible selected-line indicator. Dependency rows already
  provide precise locations, but users need to verify them in the inspector.
- Preserve useful window/splitter/column settings, offer a compact layout, and avoid relying
  on language color alone in the file tree.
- Replace the plain health dump with a concise coverage summary and links to affected files.
- Validate text contrast, zoom and focus visibility as a dedicated accessibility pass;
  no formal contrast-conformance claim is made by this audit.

## Recommended correction sequence

1. Project/request isolation, cancellation and process error handling (UI-02, UI-03, UI-07).
2. Responsive Qt/web layout and visible edge evidence (UI-01, UI-05).
3. Tree queries, confidence and filter consistency (UI-04, UI-06, UI-08).
4. Keyboard accessibility and the additional usability improvements (UI-09).

Each correction should begin with a regression test asserting the desired behavior. Convert
the relevant audit probe rather than adding an assertion that perpetuates the defect. Keep
the 20 existing UI tests and add real viewport, project-switch, failure and keyboard scenarios.
